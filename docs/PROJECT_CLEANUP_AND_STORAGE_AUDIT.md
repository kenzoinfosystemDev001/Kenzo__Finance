**Videos are not supported.** The upload validator (`file-validation.ts`) accepts PDF,
PNG, JPEG, WEBP, TIFF and text files. No video type exists, so nothing video-related is
stored today.

## 6. Server and HTTP caching

- Every server-side API call goes through `apiFetch`, which sets `cache: 'no-store'`. Business
  records are not served from the Next data cache.
- Export, document and content routes all set `cache: 'no-store'`.
- Writes call `revalidatePath` for the affected pages.
- Profile photos and the logo use `private, no-cache` / `public, no-cache` with a content-hash
  ETag, so a replaced image is never shown stale.
- Redis or any other server cache: **none**. No CDN or reverse proxy configuration in the repo.
- **Not verified:** whether logout clears every in-memory Next router cache. The cookies are
  cleared; the router cache is per-tab memory and is discarded on reload.

## 8. Decisions needed

1. **Storage architecture.** Options:
   - **A. Hybrid (recommended).** Keep Cloudinary for documents and any large files. Keep
     Postgres for small images (profile photos, the logo, ~512 px, a few KB each). Metadata
     and ownership stay in Postgres in both cases. Cheapest and avoids bloating database
     backups.
   - **B. Everything in Postgres.** Moves existing documents out of Cloudinary into `bytea`.
     Trade-offs: database size and backup time grow with every PDF, and existing files need
     a migration with no rollback once Cloudinary copies are deleted. Not recommended for
     large files.
2. **Apply `20261204090000_brand_logo` to Neon** (and stop the running API first so the
   Prisma client can be regenerated).
3. **Generated caches**: approve deleting `.next/`, `tsbuildinfo`, and `dist/` (with a rebuild).
4. **Dependency scan**: approve running `depcheck` (read-only) and removing anything it shows
   as unused.
